# Genesis 总体设计

Genesis 是一组可组合的 Go 微服务组件，不是应用框架。应用负责创建组件、注入
依赖并管理生命周期；Genesis 只提供边界清楚的能力积木。

## 核心原则

- 显式装配配置、日志、连接器与业务组件，不使用运行时 DI 或全局注册。
- 包按能力分层、目录保持扁平，可以独立导入。
- 谁创建资源，谁负责关闭；上层组件借用 Connector，不反向关闭它。
- 统一 API 保留后端在一致性、确认、TTL 和故障恢复上的差异。

| 层次 | 组件 | 职责 |
| :--- | :--- | :--- |
| 基础能力 | `clog`、`config`、`metrics`、`trace`、`xerrors` | 统一工程约束 |
| 基础设施 | `connector`、`db` | 外部连接和数据库访问 |
| 业务能力 | `cache`、`idgen`、`dlock`、`idem`、`mq` | 通用业务能力 |
| 服务治理 | `auth`、`ratelimit`、`breaker`、`registry` | 服务调用与流量治理 |

## 装配与释放

先加载配置，再初始化可观测性、连接器、业务组件和服务器。
退出时按相反顺序停止服务、后台任务并关闭资源。
组件自行创建的 goroutine、watcher、租约和订阅由组件的关闭接口结束。

## 模块与测试边界

Genesis 保持一个 Go module，统一版本避免组件版本组合问题。
`internal/testkit` 管理仓库内的真实容器测试；外部项目维护自己的 fixture。
CI 不依赖下游仓库，不把业务系统验收绑定为组件库的日常检查。

接口、后端差异和错误语义以各组件 README 与 GoDoc 为准。
