# v0.6.0 开发计划

**目标**：纯体验优化，不新增功能。修复存量 bug、消除规范违规、对齐 API 行为、补充测试保护力。

## P0 — 用户直接踩坑的硬伤

### 1. 309 处 `assert` 违规 → 全部改 `require`

项目规范要求使用 `testify/require`，`assert` 遇到失败会继续执行，掩盖真实错误。

| `auth/auth_test.go` | 68 |
| `ratelimit/grpc_test.go` | 37 |
| `ratelimit/middleware_test.go` | 41 |
| `ratelimit/distributed_test.go` | 44 |
| `ratelimit/standalone_test.go` | 39 |
| `connector/integration_test.go` | 48 |
| `db/integration_test.go` | 32 |

### 2. `connector.NewXxx` 全部缺 nil 守卫

7 个构造函数（`NewMySQL`/`NewRedis`/`NewEtcd`/`NewNATS`/`NewKafka`/`NewSQLite`/`NewPostgreSQL`）传 nil cfg 直接 panic，而其他组件都有 nil 守卫。需要：

- 统一加 `cfg == nil` 守卫，返回有意义的错误
- `connector/config.go` 各 `validate()` 补字段级错误消息（现在只返回裸 `ErrConfig`，不说哪个字段非法）

### 3. 14 处硬编码 `==` 错误比较 → `errors.Is`

错误被 wrap 后 `==` 直接漏判，是静默 bug：

| 文件 | 行 | 问题 |
|------|-----|------|
| `breaker/interceptor.go` | 68, 70 | `err == context.Canceled` / `err == context.DeadlineExceeded` |
| `cache/redis.go` | 334 | `err == redis.Nil` |
| `idem/redis.go` | 38, 57, 101, 123, 135 | `err != redis.Nil` / `err == redis.Nil` |
| `mq/redis_stream.go` | 143, 184, 225 | `err == redis.Nil \|\| err == context.Canceled` |
| `config/viper.go` | 84, 150, 403 | 类型断言替代 `errors.As` |

### 4. `clog` 四处 `fmt.Errorf` → `xerrors`

违反项目规范，外部用 `xerrors.Is` 匹配这些错误会失败：

| 文件 | 行 |
|------|-----|
| `clog/clog.go` | 18 |
| `clog/config.go` | 73 |

| `clog/level.go` | 67 |

## P1 — 资源安全与可预测性

### 5. `ratelimit/standalone.go` Close 并发 panic

`Close()` 用 `select default` 实现幂等，没有 `sync.Once`，并发两次调用会 `close` 已关闭的 channel，直接 panic。改为 `sync.Once`。

位置：`ratelimit/standalone.go:208-217`

### 6. `idem/memory.go` 无后台清理，长期运行内存泄漏

`memoryStore` 只在 `GetResult` 命中过期 key 时才清理，"只写不读"场景下内存永不释放。需要加一个启动时的 cleanup ticker，定期扫描过期条目。

位置：`idem/memory.go:83-110`

### 7. `registry.Close` 硬编码 5s timeout

`registry.go:569` 自己起 `context.WithTimeout(context.Background(), 5*time.Second)`，调用方无法控制等待时长。改为接受调用方传入的 ctx，没有 deadline 时再 fallback 到 5s。

### 8. `db` 慢 SQL 阈值 200ms 硬编码

`db/gorm_logger.go:74` 慢查询阈值不可配置。加 `WithSlowThreshold(d time.Duration)` option，默认值保持 200ms 不变。

## P2 — API 清理与一致性

### 9. 删死代码

| 位置 | 内容 |
|------|------|
| `auth/auth.go:351` | `parseClaimsWithoutTimeValidation` — 全库无引用 |
| `auth/auth.go:382` | `hasAnyAudience` — 全库无引用 |
| `dlock/redis.go` | `lockWithRetry` 的 `tryOnce bool` 参数 — 唯一调用点永远传 `false` |

### 10. `connector` 和 `registry` 补 `WithMeter`

auth/cache/idem/idgen/mq/ratelimit 都有 `WithMeter`，连接层和注册中心反而没有，不对称。连接池健康指标（连接数、重连次数）无法接入 metrics。

### 11. `idgen.UUID()` 吞错误

`idgen/uuid.go:15` `v7, _ := uuid.NewV7()`，熵枯竭时静默返回空字符串。改为返回 `(string, error)` 或加 fallback + log。

### 12. breaker 4 处无效测试断言

测试看起来绿但没有保护力：

| 位置 | 问题 |
|------|------|
| `breaker/breaker_test.go:105-107` | 只 `t.Log`，失败不会 fail |
| `breaker/breaker_test.go:127` | 永真条件分支，无判别力 |
| `breaker/breaker_test.go:258` | fallback 未被调用也不 fail |
| `breaker/breaker_test.go:286-305` | 只检查非 nil |

## P3 — 文档对齐

### 13. `registry.New` nil cfg 行为不一致

其他组件 nil cfg 返回 error，`registry.New` 静默替换为默认值（`registry.go:73-75`）。两种做法选一个，并在文档里说清楚。

### 14. TTL 单位不统一，文档未说明

| 组件 | 字段 | 类型 |
|------|------|------|
| `idgen.SequencerConfig.TTL` | TTL | `int`（秒）|
| `cache.DistributedConfig.DefaultTTL` | DefaultTTL | `time.Duration` |
| `idem.Config.DefaultTTL` | DefaultTTL | `time.Duration` |

在各自 README 里交叉注明，避免用错单位。

### 15. `trace.Discard` 命名有误导性

`clog.Discard` 是真 no-op，`trace.Discard` 会修改全局 TracerProvider，两者名字相同但副作用完全不同。在 `trace/README.md` 和 `trace/noop.go` godoc 里加粗提示，或重命名为 `InstallNoopTracing`。
